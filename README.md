# Бронирование переговорной комнаты

Интерфейс бронирования одной переговорной комнаты в течение рабочего дня (09:00–18:00): выбор даты, просмотр броней на дне в виде таймлайна, создание, редактирование и удаление. Бэкенда нет: API имитируется в браузере.

Репозиторий: https://github.com/dnaseven/tt-room-booking

Затраченное время: около 4,5 часов (по времени коммитов 29.10.2026: с 17:44 до 22:16, с короткими перерывами)

## Стек

- React 19, TypeScript, Vite
- TanStack Query для запросов и инвалидации списка
- zod для схем и валидации
- MSW (service worker) для мок-API, localStorage как хранилище
- Tailwind CSS 4, shadcn/ui, lucide-react
- react-i18next (английский и русский)
- Vitest и Testing Library для unit- и компонентных тестов, Playwright для e2e
- oxlint для линта

## Как устроено

Код разделён на три слоя с импортами через алиасы `@client/*`, `@server/*`, `@domain/*`.

- `src/domain` — zod-схемы, коды ошибок, чистые бизнес-правила и use case'ы (`createBooking`, `updateBooking`, `deleteBooking`, `listBookings`) поверх интерфейса репозитория. От `client` и `server` не зависит.
- `src/server` — мок-API: обработчики MSW (`api`), репозиторий на localStorage (`infra`), запуск воркера. Задержка ответа 400 мс. Правила применяет те же use case'ы из домена.
- `src/client` — клиент. Общается с сервером только по HTTP (`/api/*`).
  - `api` — fetch-клиент, ответы валидируются схемами, ошибки приводятся к `ApiError` с кодом. API передаётся в хуки через контекст, поэтому заменяется на реальный без правок UI.
  - `features/booking` — экран, хуки TanStack Query, маппинг DTO в UI-модели.
  - `ui` — презентационный слой без знания об api, домене и i18n: данные и готовые строки приходят пропсами.
- `src/bootstrap` — точка входа: сначала запускается мок-сервер, затем рендерится клиент.

UI построен по атомарному дизайну (atoms, molecules, organisms, templates, pages). Компоненты shadcn (`ui/vendor/shadcn`) и иконки lucide импортируются только в атомах, остальные уровни только компонуют атомы.

### Контракт API

```
GET    /api/bookings?date=YYYY-MM-DD
POST   /api/bookings
PATCH  /api/bookings/:id
DELETE /api/bookings/:id
```

```ts
type Booking = {
  id: string
  date: string // YYYY-MM-DD
  start: string // HH:mm
  end: string // HH:mm
  title?: string
}
```

Коды ответов: 201 на создание, 204 на удаление, 400 на нарушение правил или некорректный ввод, 404 если брони нет, 409 при пересечении, 500 на непредвиденную ошибку. Тело ошибки: `{ code, message }`.

## Бизнес-правила и принятые решения

Правила реализованы в `src/domain/booking/booking.rules.ts` и используются и сервером, и клиентом (клиент проверяет их перед отправкой формы).

Порядок проверок: формат входа, затем `start < end`, затем границы рабочего дня, затем длительность (минимум 30 минут, максимум 2 часа), затем прошедшее время, затем пересечения с другими бронями.

Там, где ТЗ молчит:

- Слот, который уже начался, считается прошедшим: в 09:10 слот 09:00–09:30 недоступен для брони.
- Касание границ (10:00–11:00 и 11:00–12:00) не считается пересечением.
- При редактировании бронь не конфликтует сама с собой.
- Если при редактировании дата и время не изменились (например, меняется только название), проверка прошедшего времени не применяется, и уже начавшуюся бронь можно переименовать.
- Пустое название при редактировании очищает старое.
- Шаг выбора времени в форме — 30 минут.
- Дата и время считаются в локальном часовом поясе браузера; время хранится строкой `HH:mm`, поэтому переход на летнее время расчёты не затрагивает.
- Конфликт 409 (или 404) показывает сообщение, список броней перезапрашивается, введённые в форме значения сохраняются.

Тексты ошибок выбираются по коду (`src/client/i18n/en.ts`, `ru.ts`): `INVALID_INPUT`, `INVALID_RANGE`, `OUT_OF_WORK_HOURS`, `DURATION_TOO_SHORT`, `DURATION_TOO_LONG`, `PAST_TIME`, `BOOKING_CONFLICT`, `BOOKING_NOT_FOUND`, а также клиентские `INTERNAL_ERROR`, `NETWORK_ERROR`, `INVALID_RESPONSE`.

## Что сделано

- Выбор даты: поле даты, предыдущий и следующий день, «Сегодня».
- Просмотр броней на выбранную дату в виде таймлайна по 30-минутным слотам; занятые и прошедшие слоты недоступны для выбора.
- Создание, редактирование и удаление (с подтверждением) брони; выбор времени начала и окончания.
- Все бизнес-правила из ТЗ, на клиенте и на сервере.
- Состояния UI: загрузка, пустой день, ошибка загрузки с повтором, отправка формы, ошибки полей и формы.
- Обработка серверных ошибок, включая конфликт 409.
- Отдельный сетевой слой, заменяемый на реальный API.
- Адаптивная раскладка: на узких экранах форма открывается поверх страницы.
- Переключение языка (английский, русский) с запоминанием выбора.
- Тесты: 253 unit- и компонентных теста в 31 файле (домен, сервер, API-слой, хуки, UI, экран целиком) и 22 e2e-сценария.

## Что не сделано или упрощено

- Текущее время не обновляется по таймеру: пометка «прошедший слот» пересчитывается только при перерисовке, а выбранная дата не меняется после полуночи без перезагрузки страницы.
- Пересечение с другими бронями проверяется только на сервере: форма не предупреждает о нём до отправки, пользователь видит ответ 409.
- Доступность проверялась не полностью: автоматической проверки (например, axe) нет; мобильная панель не переносит фокус в форму, не закрывается по Esc и не удерживает фокус. Контраст приглушённого текста на прошедших слотах не измерялся.
- Данные хранятся только в localStorage браузера; нет общего состояния между пользователями, а чтение и запись хранилища неатомарны при нескольких вкладках. Невалидные записи в localStorage при чтении отбрасываются.
- Один часовой пояс (локальный часовой пояс браузера); серверная часть использует часы клиента.
- В форме можно выбрать другую дату; после сохранения просматриваемый день не переключается на дату брони.
- Длина названия не ограничена.
- Размер продакшн-бандла около 880 КБ (около 305 КБ gzip): в него входят MSW и остальные библиотеки, разбиения на чанки нет, сборка выводит предупреждение Vite о размере чанка.
- `lang` в `index.html` не меняется при переключении языка.
- Демо с MSW ожидает, что воркер доступен в корне сайта (`/mockServiceWorker.js`); развёртывание в подкаталог не проверялось.
